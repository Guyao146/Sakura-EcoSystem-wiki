# 贡献与维护

## 文档约定

- 文件名使用小写英文和短横线，正文使用简体中文。
- 先写用户要完成的任务，再写实现细节。
- 命令必须可复制，密钥只使用占位符。
- 版本号、配置项和接口路径以源码为准，不凭记忆补全。

## 变更流程

1. 在对应项目仓库确认行为和版本。
2. 更新本 Wiki 的项目页或架构页。
3. 本地启动静态服务器检查导航、代码块和移动端布局。
4. 提交清晰的变更说明并推送 `main`。
5. 观察 `wiki.mcylyr.cn` 更新结果。

## 维护边界

Wiki 不复制两个项目的全部源码，也不替代各自 README、CHANGELOG 和 Issue。这里保留跨项目关系、部署决策和面向使用者的操作路径；详细实现问题应回到对应仓库讨论。
