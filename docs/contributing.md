# 贡献与维护

> Wiki 文档版本：`v1.1.0` · 更新日期：`2026-10-02`（贡献与维护独立版本）

## 许可证

[Sakura-License v1.2](sakura-license.md) 当前为审阅稿，不因本页更新自动适用于贡献。根 [LICENSE](../LICENSE) 仍为 GPL-3.0，先前 Wiki 的 Sakura-License 声明与其范围存在未解决冲突，详见 [采用与授权指引](sakura-license-adoption.md)。不要以“根文件仅作历史参考”或新增说明覆盖第三方已经合法取得的权利。

提交内容应保留来源、版权与适用许可证。迁移范围或贡献授权不明确时，合并前应由维护者与贡献者明确确认；不得将提交 PR 自动解释为版权转让、闭源商业再许可或历史侵权诉讼授权。需要额外权利时应事先展示独立协议、核实权利主体并保存同意记录，新条款不追溯适用于旧贡献。

各上游代码仓库继续按自身有效许可及声明处理，不因 Wiki 新稿而改许可。引用代码或为其贡献补丁时，应核实对应版本的实际许可证，不仅凭本 Wiki 的历史扫描结论。

## 维护边界

Wiki 不复制各项目的全部源码，也不替代各自 README、CHANGELOG 和 Issue。这里保留跨项目关系、部署决策和面向使用者的操作路径；详细实现问题应回到对应仓库讨论。

## 设计规范

页面排版、组件写法、章节顺序与写作语气，统一遵守 [设计规范](design-guide.md)。新增或修改页面之前先读它。要点：

- 项目页章节顺序固定，快速开始必须出现在前三节之内。
- 每页结尾保留固定的免责声明。
- 表格不超过 4 列，状态列写文字不写反引号。
- 代码块必填语言标记，命令前说明「做什么」，命令后说明「成功标志」。

## 版本规则

- 每个项目或专题页面独立递增 Wiki 文档版本；修改一个页面时，不要求其他页面一起升版本。
- 版本头固定写在正文第 3 行，格式为 `> Wiki 文档版本：vx.y.z · 更新日期：YYYY-MM-DD（…独立版本…）`。
- 纯内容勘误升补丁位；新增章节或重写主要段落升次版本位。
- 上游项目版本以对应仓库的版本文件和 CHANGELOG 为准，不跟随本页版本号一起动。
- 页面版本号变更后，同步更新 [README](../README.md) 项目表的版本列与 [CHANGELOG](../CHANGELOG.md) 的总表。

## 链接规范

- 文档之间用相对链接（如 `[设计规范](design-guide.md)`），不写完整 URL。
- 引用仓库用完整 GitHub URL；引用 Wiki 内页面一律相对路径。
- 提交前确认所有相对链接可解析。

> 文档基于对应项目源码整理。实现变更后，以项目仓库、版本文件和 CHANGELOG 为最终依据。
