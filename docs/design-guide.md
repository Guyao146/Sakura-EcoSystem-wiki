# 设计规范

> Wiki 文档版本：`v1.2.0` · 更新日期：`2026-10-03`（设计规范独立版本）

本页是樱落生态 Wiki 的设计语言规范。写作新页面或修改现有页面时，以此为准；本规范本身也遵循它。

## 设计哲学

界面是枝干，内容是樱花。枝干要让人看见花，而不是看见枝干。

四个原则，前两条取自 Apple Human Interface Guidelines，第三条取自小米澎湃OS 的「生命感美学」，第四条是文档站自身的底线：

| 原则 | 含义 | 在本 Wiki 上的表现 |
| --- | --- | --- |
| **退让 Deference** | 界面衬托内容，不与之争夺注意力 | 去掉不必要的边框和装饰，留白即结构 |
| **通透 Translucency** | 层次靠明度差和阴影，不靠框线 | 表格与代码块用背景色差加轻阴影分区 |
| **回响 Response** | 操作有可见反馈 | 链接与按钮在 hover 时有 150–200ms 的柔和过渡 |
| **一致 Consistency** | 同类元素在全站长一样、叫法一样 | 章节顺序、徽章、表格列与结尾声明全部模板化 |

不做的事：页面级动画、滚动视差、发光呼吸效果。文档站要安静。

## 页面结构模板

项目页按此顺序组织章节，位置不可调换：

```text
# 项目名
> 版本头（固定格式，见下）
徽章行（生态成员 / 项目 / 已编写Wiki，顺序固定）
## 项目定位       是什么 → 解决什么 → 不是什么，三段式
## 快速开始       位于前三节之内，代码块 + 1–4 步编号列表 + 一段补充说明
## 当前状态       键值表：版本 / 运行要求 / 依赖 / 认证 / 存储…
## 功能概览       领域-能力两列表
## 架构           ASCII 图 + 模块清单
## 领域专用章节    按项目裁剪，如环境变量、可靠性设置、部署
## 与生态其他项目的关系   每页必有
## 版本记录       版本-要点表
> 结尾声明        每页必有，逐字固定
```

专题页（部署、运维、安全、贡献、本页）不强制套用项目模板，但版本头与结尾声明仍然必须有。

## 版本头

固定格式，位置恒为正文第 3 行（标题与正文之间，不留空行以外内容）：

```text
> Wiki 文档版本：`vx.y.z` · 更新日期：`YYYY-MM-DD`（某某独立版本）
```

版本号规则见 [贡献与维护](contributing.md)。修改一页只升这一页的版本，不要求其他页面同步升。

## 内容组件

### 徽章行

紧跟版本头，顺序固定为生态成员徽章、项目徽章、已编写Wiki 徽章。徽章来源统一放在 `assets/`，不引用会失效的外链图床。

### 表格

- 表头左对齐，用名词短语，不用完整句子。
- 同一张表不超过 4 列；信息多时拆成多张分组表，而不是加列。
- 状态列直接写文字（如「已实现」「计划中」），不用反引号包裹，不用表情符号。
- 单元格内不放长段落，长说明移到表下正文。

### 代码块

- 语言标记必填（` ```bash `、` ```powershell `、` ```text `），触发正确的高亮。
- 命令前给一句「这条命令做什么」，命令后给一句「看到什么算成功」。
- Windows 与 Linux/macOS 命令分开给，不混排在同一块里。

### blockquote

- 纯提示与注意事项用普通 blockquote。
- `> [!WARNING]` 只用于部署类高风险操作（如「丢失后不可恢复」），日常提示不用。
- blockquote 一段只装一条提示，不堆叠多条。

### ASCII 架构图

统一用 ` ```text `，箭头符号统一为 `│ ▼ ── ┌ └`，块内不留多余空行，图后紧跟一段文字解释。

### 快速开始

代码块在前，编号步骤在后，最后一段 blockquote 收尾补充前置条件与边界。步骤不超过 4 步，超过的拆成「第 1 步 / 第 2 步」子标题（UniLink 的写法可作参照）。

### 结尾声明

每个项目页最后一句，逐字固定：

```text
> 文档基于对应项目源码整理。实现变更后，以项目仓库、版本文件和 CHANGELOG 为最终依据。
```

## 排印

字体栈保持现有的 PingFang SC → Microsoft YaHei → system-ui，不引入网络字体。

| 层级 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| h1 | 2.25rem | 700 | 页面名，每页仅一个 |
| h2 | 1.55rem | 650 | 一级章节 |
| h3 | 1.22rem | 625 | 二级章节 |
| 正文 | 16px | 400，行高 1.7 | 段落 |
| 表格小字 | 14px | 400，行高 1.5 | 表格与徽章旁说明 |

标题用字重阶梯而非只靠字号分层：二三级标题过去同为 700，扫一眼分不出层级。

行内代码去掉边框，只用底色区分，减少视觉噪音。

## 间距

4px 基准网格，间距只从这八个值里取：

```text
4 · 8 · 12 · 16 · 24 · 32 · 48 · 64
```

- 章节之间 32 以上，段落之间 16。
- 表格单元格 10×14。
- 同组元素间距小，跨组间距大——让留白代替分隔线做分组。

## 分区与层次

用「面」代替「框」：

| 元素 | 规范 |
| --- | --- |
| 表格 | 去外边框；行间用极细分隔线；表头底色微深；整块轻投影、圆角 |
| 代码块 | 去边框，靠背景明度差区分，圆角加轻投影 |
| blockquote | 保留左侧强调线，加一层极浅底色 |
| 侧栏 | 去右边框，玻璃化（背景模糊），与内容区用明度差分开 |

投影分两级：静止用轻投影，hover 抬升时加深一级。

### 圆角体系

| 元素 | 圆角 |
| --- | --- |
| 面板、弹层 | 12px |
| 按钮、输入框 | 8px |
| 徽章、芯片 | 全圆 |

圆角和投影一样是分层的语言：越大越「面」，越小越「控件」。不要中途自造 6px、10px 这类中间值。

## 反馈

- 链接与按钮 hover：颜色渐变、轻微上抬 1px、投影加深。
- 过渡时长 150–200ms，缓动 `ease`。
- 侧栏当前项加左侧 2px 指示条，不只靠字色。

## 色彩

色彩 token 的**角色**固定，色值可调：

```text
--page          页面底色
--surface       侧栏与面板，比 page 深一层
--surface-soft  表头、代码块、hover 底
--text          正文
--text-soft     次要文字
--muted         辅助与占位
--heading       标题
--accent        主强调：链接、当前项、引用线，全站唯一的品牌出口
--accent-strong hover 与激活态
--border        极弱，仅用于不可替代的分割
--code-bg / --code-text
--shadow        轻投影
```

用法纪律：

- 一页最多一处「重」强调色块。
- 明暗两套 token 同构，只换值不改结构。
- 正文对比度达到 WCAG AA（4.5:1）。

参考色值（登录页等品牌页面所用，可作为新页面取值的起点）：

| token | 日间 | 夜间 | 说明 |
| --- | --- | --- | --- |
| `--page` | `#fff` | `#1b1b1f` | 页面底色 |
| `--surface` | `#f7f7f8` | `#171719` | 面板，比底色深一层 |
| `--surface-soft` | 再深一层 | 再深一层 | 软底：表头、代码块、hover |
| `--accent` | `#b84d66`（樱色） | `#ef9aab`（浅樱） | 全站唯一的品牌出口 |
| 渐变 | `#b84d66 → #7c3aed` | `#8f3a50 → #5326b8` | 150deg，夜间加深防眩光 |

三级明度差（底色 → 面板 → 软底）代替边框做分区；输入框这类需要边界感的控件只用 1px 弱边，不用粗边框。夜间渐变刻意压深，避免大面积亮色在暗环境下眩光。

## 登录页与品牌页面

登录页和门户、授权页、控制台共用同一套骨架与 token。桌面端用 `brandPage` 分栏骨架：

- 左右 50/50。左侧是全页**唯一**的重色块——150deg 樱色→紫罗兰渐变面板，内容垂直居中、左对齐：圆角芯片里的樱花标 → 大标题 → 口号 → 三条带图标的产品特性；右下角一枚 `opacity:.12` 的超大樱花装饰。
- 右侧表单面板只做一件事：安静地承接输入。标题、输入框、主按钮全部沿用中性 token，不与渐变面板抢色。
- 窄屏（≤899px）整体隐藏渐变面板，由表单顶部一行紧凑品牌行承接识别——手机上不堆砌。
- 零 JavaScript、零外部字体：字体栈 PingFang SC → Microsoft YaHei → system-ui，整页就是一份 HTML 加一段内联 CSS。

纪律：因为「一页最多一处重强调色块」的名额给了左侧品牌面板，右侧表单就不能再出现第二个重色块。这条规则同样适用于其他品牌页面——选定主角以后，其余元素只能退让。

## 写作语气

- 结论先行：第一句是结论，再讲理由。
- 定位用「是 / 不是」对照式写。
- 用「你」，不用「我们」「大家」。
- 操作给命令式短句，事实给陈述句。

## 参考实现

这套语言在生态项目里的唯一样式来源是 `src/views/layout.js` 中的 `SAKURA_CSS`（约 200 行：设计 token + 组件样式 + 明暗两套主题），全站每一页都从这一份样式表出发，Wiki 站点自身的 `assets/theme.css` 遵循同样的 token 结构。

想在其他项目复用，最省事的路径是把 `SAKURA_CSS` 整段搬走——它自包含（变量 + 组件 + 两套主题），不依赖任何构建工具。品牌色只需在管理端「品牌定制」里修改 `--accent` 等变量，整套派生色（渐变、对比文字色）自动跟随变化；改动色值时要保持本节「色彩」部分的角色结构和明度差规则。
